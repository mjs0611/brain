# 증상을 문제로, 가설을 원인으로 바로 승격시키지 않는다

> 문제를 올바르게 적는 일 — 누구의 문제인가 / 무엇과 비교해 문제인가 / 언제까지 어떤 상태가 해결되어야 하는가 → 기준선, 당사자, 범위와 기한, 성공 조건, 제약 명확해야 함.
> 증상 → 문제 → 원인의 구분. 증상: 겉으로 관측된 현상. 문제: 목표와 현실의 격차를 이해관계자 관점에서 정의. 원인: 격차를 만드는 기제.
> 증상을 문제로, 가설을 원인으로 바로 승격시키지 말 것.
> ∴ SCQA: 상황(Situation) → 문제 발생(Complication) → 질문(Question) → 답(Answer)
> — 필기 (June 요약)

**해석.** 기존 노트(현상·원인·solution 부재)가 문제를 세 덩어리로 갈랐다면, 이 페이지는 **승격 단계에서 생기는 오류**를 짚는다. 관측(증상)과 추측(가설)은 둘 다 머릿속에서 너무 쉽게 사실로 굳는다.

"문제"의 정의가 날카롭다. 격차다. 기준선이 없으면 격차가 없고, 격차가 없으면 문제도 없다. "전환율이 낮다"는 무엇과 비교해 낮은지 말하지 않으면 증상일 뿐이다. 그래서 문제 문장엔 누구·비교 대상·기한·성공 조건이 반드시 들어가야 한다.

SCQA는 이렇게 정의한 문제를 남에게 전달하는 순서다. Complication이 곧 격차이고, 격차가 정확해야 Question이 하나로 좁혀진다.
